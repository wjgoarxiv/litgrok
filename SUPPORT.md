# Support

Start with the [operational reference](./docs/reference.md) or [한국어 안내](./docs/reference_ko-KR.md). Check the selected project/user scope and whether your terminal invocation was a no-write preview before reporting missing files.

For bugs or questions, use Issues in the repository identified by `plugin.json`: [wjgoarxiv/litgrok](https://github.com/wjgoarxiv/litgrok). This is the source identity, not a claim that a future public release or support channel is already reachable. If you cannot access Issues, keep a local report until the release channel is available. No support SLA is promised.

Provide package and Node versions, OS, command, expected result, actual result, and a synthetic reproduction. State whether evidence came from source tests, an installed tarball, or your authenticated Grok session. Attach only redacted excerpts. Use the security process for sensitive issues, and review [local data handling](./docs/privacy.md) before sharing logs.

LitGrok does not provide Grok credentials, grant hook trust, choose models, or manage provider billing. Consult the host's own support for those concerns. Local installer success does not establish host discovery or authenticated runtime behavior.
