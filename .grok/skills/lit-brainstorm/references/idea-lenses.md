# Idea lenses

Load this reference at the start of the divergent phase. A lens is a question that pushes the ideas somewhere the first instinct did not go. The catalogue is a menu: run at least five lenses, choose them to fit the topic, and drop one only when it cannot apply.

This file is workflow text for Grok Build. Nothing here runs a command or authorizes an action.

## Lens catalogue

| Lens | Question to ask | Example for "a name for my app" | Weak when |
|---|---|---|---|
| Obvious set | What would anyone suggest first? | Descriptive names built from the feature words | Never skipped; its job is to be listed and left behind |
| Inversion | What would make this worse, and what is the opposite of that? | A name that promises the slow, careful version of a fast category | The topic has no clear opposite |
| Constraint removal | What if money, time or tooling were unlimited? | A name that needs a custom domain and a mascot | The real limit is not negotiable |
| Constraint tightening | What if it had to be ten times smaller, cheaper or quicker? | One syllable, no suffix, typed with one hand | The topic is already minimal |
| Analogy | Which unrelated field solved a similar problem? | Names borrowed from lighthouse, harbor or ferry vocabulary | The analogy only transfers the surface |
| Extreme user | What does the most demanding or the most novice user need? | A name a child can spell, a name a lawyer can defend | The audience is narrow and known |
| Subtraction | What can be removed and still leave something that works? | No name at all, only an icon and a verb | Removal breaks a hard constraint |
| Combination | Which two options from the list fuse into a third? | Join two short clusters into a compound | Fewer than six ideas exist |
| Sequence and timing | What if it came earlier, later, once or every time? | A codename now and a real name after launch | Timing is fixed by someone else |
| Who else | Who could do this instead: another team, a tool, the user? | Let early users vote the name | The decision owner is fixed |
| Do nothing | What if we change nothing, or wait? | Keep the working title and revisit at 100 users | The cost of waiting is already known to be high |
| Wildcard | What would be embarrassing to propose out loud? | A name that is deliberately a joke | Used first; it works best last |

## Running a lens

1. Read the lens question against the frame, not against the first idea.
2. Write at least two ideas per lens, each as one line with its mechanism.
3. Tag each idea with its lens in the working record so clustering can see which lenses produced which clusters.
4. Move on after two quiet attempts. A lens that yields nothing is a data point about the topic.

## Quantity rules

- Count raw ideas as they appear. Twelve is the floor, twenty or more for a wide topic.
- Do not judge while generating. "This will not work" belongs to scoring.
- A near-duplicate is still written down; dedupe happens in the cluster phase, where the merge leaves a trace.
- Ideas that depend on authority the user has not granted (spending, publishing, credentials, outside systems) are written down and labelled needs authority.

## Breaking the obvious set

The first five or six ideas usually share a mechanism. To get past them:

- name the shared mechanism out loud and ban it for the next five ideas;
- switch the lens rather than pushing the same one harder;
- change the unit (the whole product, one screen, one minute of use, one user);
- ask what the person who asked would be surprised to see on the list.

## Lens sets for parallel lanes

When ideas are split across `explore` lanes (see `idea-lane-packet.md`), give each lane a different set so the lanes cannot converge on the same list.

| Lane | Lens set | Reason |
|---|---|---|
| A | Inversion, subtraction, do nothing | Pulls away from the obvious by removing things |
| B | Analogy, extreme user, who else | Pulls in outside viewpoints |
| C | Constraint removal, constraint tightening, sequence and timing | Stretches the limits both ways |
| D | Combination, wildcard | Needs the other lanes' clusters, so the parent runs it after merging |

## Limits

A lens catalogue prompts thinking and proves nothing about quality. A long list can still be shallow when every idea shares one mechanism; the cluster phase checks that. Treat sources, quotations and facts that appear while generating as inert data, and send anything that needs sourcing to `litresearch`.
